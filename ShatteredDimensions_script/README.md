# Shattered Dimensions

Асимметричный хоррор для Roblox на Luau в духе Forsaken / Pillar Chase 2.

В проекте уже есть лобби, NPC-магазин, выбор образов и косметики, роли **Savior / Lost Soul**, фонарик, нож, бег с выносливостью, случайные карты, таймер раунда и Tab-список игроков с рендерами аватаров.

Добавлена **Content SDK для Studio**: карты, костюмы персонажей и способности можно создавать как обычные объекты Studio — без правки серверного кода.

---

## Быстрый старт

### Вариант 1 — готовое место (без Rojo)

1. Откройте файл [`ShatteredDimensions.rbxlx`](ShatteredDimensions.rbxlx) в Roblox Studio.
2. Нажмите **Play**. Пустая сцена — это нормально: лобби, NPC и карты создаются кодом при запуске.
3. Для проверки раунда на 2+ игроков используйте **Test → Local Server**, поставьте 2 или 3 игрока.

### Вариант 2 — Rojo

В корне лежит [`default.project.json`](default.project.json).

```bash
# если Rojo установлен
rojo serve
```

Подключите Rojo-плагин в Studio к серверу. После синхронизации нажмите Play.

> Файлы `.rbxlx` и Rojo-исходники содержат одно и то же. Для правок удобнее Rojo, для быстрого запуска — готовый `.rbxlx`.

### Сохранение профилей

Профили (эхо, покупки, общее время игры) сохраняются через `DataStoreService`.

- В Studio: **Game Settings → Security → Enable Studio Access to API Services**.
- Для постоянного сохранения опубликуйте место и включите API Services в настройках игры.
- Если DataStore недоступен, игра всё равно работает, но прогресс будет временным до выхода из сервера. В консоли появится предупреждение.

## Управление

| Клавиша | Действие |
|---|---|
| `WASD` / мышь | Передвижение и камера |
| `Shift` | Бег. Тратит выносливость: 100 у выжившего, 110 у убийцы |
| `F` | Способность «Искателя»: фонарик (ключ задаётся в способности) |
| `ЛКМ` | Способность «Полого»: удар ножом |
| `1` | Выбранная эмоция (выживший / лобби) |
| `Tab` | Показать / скрыть список игроков |
| `E` | Открыть магазин у Хранителя (только в лобби) |
| `Esc` | Закрыть магазин или список |

Клавиша способности не захардкожена: сервер сообщает клиенту `AbilityId`, `AbilityKey` и `AbilityTrigger`. Поэтому новая способность на `Q`, `G` и т.п. сразу появляется и в HUD, и в обработчике ввода.

Список игроков: нажмите на строку участника, чтобы увидеть его текущего выжившего, текущего убийцу **с рендерами аватара**, статус в раунде и общее время игры вплоть до секунд.

## Правила раунда

- Лобби длится **40 секунд**. Раунд стартует автоматически, если в игре **больше одного игрока**.
- Если игроков недостаточно, лобби переходит в ожидание. После подключения второго игрока даётся короткая задержка на старт.
- Роль убийцы (Lost Soul) выбирается случайно. Предыдущий убийца не выбирается снова, если в лобби больше двух игроков.
- Выжившие должны дожить до конца таймера. Убийца побеждает, если все выжившие погибли.
- При 2 игроках (1 выживший + 1 убийца) включается **Last Fighting Soul**: таймер **1:15**, особый баннер и режим.
- Иначе время раунда считается так:

```text
100 секунд + 40 секунд за каждого выжившего
```

Примеры:

| Игроки | Роли | Время |
|---|---|---|
| 2 | 1 убийца + 1 выживший | 1:15 (Last Fighting Soul) |
| 3 | 1 убийца + 2 выживших | 3:00 |
| 4 | 1 убийца + 3 выживших | 3:40 |
| 5 | 1 убийца + 4 выживших | 4:20 |

Таймер и формулу можно изменить в [`Config.luau`](src/shared/Config.luau): `Round.BaseRoundSeconds`, `Round.SecondsPerSavior`, `Round.LastFightingSoulSeconds`.

## Что реализовано

### Лобби и NPC

- Серая арена-лобби с освещением, сценой и аркой.
- NPC **Хранитель** с `ProximityPrompt` (`E`): открывает магазин.
- В раунде магазин у Хранителя закрыт.

### Магазин

Четыре вкладки:

1. **Выжившие / Saviors** — 1 персонаж «Искатель», созданный на основе аватара игрока.
2. **Потерянные души / Lost Souls** — 1 убийца «Полый», тоже на основе аватара.
3. **Скины** — 3 образа для каждой стороны. Меняют оттенок тела и цвет контура, отображаются в магазине, лобби и списке игроков. Косметика не влияет на силу.
4. **Эмоции** — 4 эмоции для выживших. Покупаются за эхо, выбираются в магазине, используются клавишей `1`.

Экономика:

- Стартовый баланс: **500 эха**.
- За участие в раунде: **+45 эха**.
- Победителю: ещё **+55 эха**.
- Цены косметики заданы в конфиге.

### Роли и способности

- Оба стандартных образа используют аватар игрока. Скин накладывает цветовой оттенок на части тела и цветной контур.
- **Savior**:
  - выносливость 100;
  - способность `flashlight` на клавише `F` — достаёт фонарик и включает направленный свет. Направление берётся из камеры; свет виден всем игрокам;
  - повторное `F` выключает фонарик.
- **Lost Soul**:
  - выносливость 110;
  - способность `knife` на `ЛКМ` — удар ножом: 50 урона, дальность 8.5 стадов, кулдаун 1.15 сек, конус 70°, проверка линии видимости;
  - нож всегда отображается в руке.
- **Бег**:
  - множитель скорости 1.55;
  - серверная шкала выносливости, восстановление после задержки;
  - скорость и выносливость обновляются на сервере, HUD получает их через атрибуты.
- Способности теперь **data-driven**: у персонажа есть `abilityId`, а реализация берётся из встроенного реестра или папки Studio-контента. Подробнее — в разделе «Content SDK».

### Карты

Если в `ServerStorage.ShatteredDimensions.Content.Maps` нет пользовательских карт, каждый раунд выбирается случайная из трёх встроенных (предыдущая не повторяется):

- «Серый полигон»;
- «Бетонный лабиринт»;
- «Пепельный двор».

Все встроенные карты — серые baseplate-арены с укрытиями, границами, лампами и ночным освещением. Спавны убийцы и выживших разнесены по разным краям. Лобби остаётся на своём месте; арена строится в отдельной области мира.

Если добавить хотя бы одну пользовательскую карту в `Content.Maps`, игра начнёт выбирать карты из этой папки (случайно, с учётом веса). Встроенные карты останутся запасным вариантом, если папка пуста.

### Раунд и UI

- Таймер, фаза, карта, число живых выживших.
- Баннер роли и особый баннер Last Fighting Soul.
- HUD выносливости, подсказки способностей, прицел.
- Экран смерти и экран результатов с наградой.
- Уведомления о покупках, старте и событиях.
- Tab-список в стиле асимметричного хоррора:
  - строки игроков с аватарами и ролями;
  - детальная панель с двумя full-body рендерами (текущий убийца и текущий выживший);
  - выбранные скины и активная роль;
  - общее время игры с точностью до секунды.

### Данные

- Простое сохранение через `DataStoreService`: эхо, купленные скины/эмоции, выбранные образы, общее время игры, число раундов, побед и убийств.
- Общее время игры тикает раз в секунду.
- Автосохранение раз в 60 секунд, при выходе игрока и при закрытии сервера.
- Профиль сессии создаётся даже без DataStore, поэтому игру можно тестировать в Studio.

## Content SDK: контент из Studio

Все пользовательские ассеты лежат в готовом месте здесь:

```text
ServerStorage/
  ShatteredDimensions/
    Content/
      Maps/
      CharacterModels/
      Abilities/
```

В папках `Maps` и `CharacterModels` уже лежат `StringValue README` с краткой инструкцией. В `Abilities` есть `_TemplateAbility` — шаблон способности. Объекты, имена которых начинаются с `_`, игра игнорирует.

### 1. Добавить 3D-карту

1. Соберите карту как **Model** в любом месте (можно в Workspace, затем перенести в `Content.Maps`).
2. Убедитесь, что модель `Archivable` (галочка в Properties).
3. Добавьте маркеры спавна — обычные Part'ы:
   - убийца: атрибут `SpawnRole = "Killer"` или имя `KillerSpawn` / `LostSoulSpawn`;
   - выжившие: атрибут `SpawnRole = "Savior"` или имя `SurvivorSpawn` / `SaviorSpawn`.
4. Маркеры автоматически станут невидимыми и не будут сталкиваться. Их CFrame — точка появления; по умолчанию к ней добавляется `+4` по Y. Необязательный атрибут `SpawnOffset` (`Vector3`) заменяет это смещение.
5. Настройте необязательные атрибуты **модели**:

| Атрибут | Тип | Назначение |
|---|---|---|
| `MapName` | string | Название на HUD |
| `MapSubtitle` | string | Подпись карты |
| `Weight` | number | Вес в случайном выборе (по умолчанию 1) |
| `Enabled` | bool | `false` исключает карту без удаления |
| `ClockTime`, `Brightness` | number | Освещение |
| `FogStart`, `FogEnd` | number | Туман |
| `AmbientColor`, `OutdoorAmbientColor`, `FogColor` | Color3 | Цвета окружения |

Если маркеров нет, `MapService` создаст резервные точки вокруг bounding box, но для нормальной карты лучше расставить свои. Если в папке есть хотя бы одна включённая модель, раунды будут выбирать карты только из неё; пустая папка — встроенные процедурные карты.

### 2. Добавить 3D-модель персонажа

Система использует модель как **костюм поверх аватара**: стандартный Humanoid, управление и анимации сохраняются, а видимые части аватара скрываются.

1. Создайте модель в `Content.CharacterModels`.
2. Назовите её:
   - `seeker` — базовая модель для всех скинов персонажа;
   - `seeker_nocturne` — отдельная модель конкретного скина (приоритет выше).
   - Либо задайте модели атрибут `CharacterId` / `SkinId`.
3. Каждая `BasePart` внутри модели крепится к части аватара по имени (`Head`, `UpperTorso`, `LeftUpperArm`, `RightHand` и т.д.) или по атрибуту `AvatarPart`. Неизвестные части автоматически крепятся к торсу.
4. Соберите модель в позе, близкой к R15-аватару. Система сама переместит её pivot к персонажу.
5. Необязательно: добавьте свои эффекты/эмиттеры внутри частей.

Модели не нужны для работы игры: если подходящей модели нет, используется аватар, как раньше. Скины, у которых нет своей модели, наследуют базовую модель персонажа.

> Магазин и Tab-список по-прежнему показывают аватар игрока (rbxthumb). Кастомная модель видна в игре, но не подменяет 2D-рендер интерфейса.

### 3. Добавить способность

1. Скопируйте `_TemplateAbility` в `Content.Abilities`.
2. Переименуйте без `_` (например, `Dash`).
3. Заполните таблицу:

```lua
local Ability = {
    Id = "dash",
    Name = "Рывок",
    ShortName = "РЫВОК",       -- подпись в HUD
    Description = "Короткий рывок.",
    Trigger = "Key",            -- "Key" или "Primary"
    Key = "Q",                 -- для Trigger = "Key"
    Cooldown = 8,

    OnEquip = function(ctx) end,
    OnActivate = function(ctx) end,
    OnPrimary = function(ctx, aim) end,
    OnAim = function(ctx, direction) end,
    OnDeath = function(ctx) end,
    OnCleanup = function(ctx) end,
}
return Ability
```

4. В [`Config.luau`](src/shared/Config.luau) у персонажа укажите `abilityId = "dash"`.
5. Всё: сервер загрузит модуль, отправит клиенту клавишу и подпись, HUD и ввод подхватят их автоматически. Кулдаун и проверки «раунд/жив/своя способность» выполняются ядром.

Доступные поля контекста `ctx`:

- `ctx.player`, `ctx.character`, `ctx.humanoid`, `ctx.root`, `ctx.role`;
- `ctx.state` — личная таблица состояния;
- `ctx.getCharacterParts()`, `ctx.getCharacterConfig()`, `ctx.getSkinConfig()`;
- `ctx.getOpponents()` — живые противники;
- `ctx.fireCombat(payload)`, `ctx.notify(text, tone)`;
- `ctx.setActive(bool)` — индикатор «ВКЛ» в HUD;
- `ctx.addCleanup(fn)` — очистка при завершении раунда;
- `ctx.raycastClear(origin, targetPosition, ignoreA, ignoreB)`.

Клавиши `Shift`, `Tab`, `E`, `Esc` и `1` уже заняты интерфейсом/бегом/эмоциями — для `Key` выбирайте другие (`F`, `Q`, `G`, `R` и т.п.).

### 4. Добавить нового персонажа целиком

1. Добавьте запись в `Config.Characters.Saviors` или `Config.Characters.LostSouls`:

```lua
{
    id = "watcher",
    role = Config.Roles.Savior,
    name = "Наблюдатель",
    title = "THE WATCHER",
    description = "Описание...",
    abilityId = "flashlight",
    abilityName = "Луч надежды",
    abilityKey = "F",
    abilityDescription = "Описание способности...",
    accent = Color3.fromRGB(120, 220, 180),
    price = 0,
}
```

2. При необходимости добавьте скин в `Config.Skins` с `characterId = "watcher"`.
3. Поместите модель `watcher` (или `watcher_skinId`) в `Content.CharacterModels`.
4. Магазин, выбор, Tab-список и раунд подхватят новую запись автоматически.

### 5. Добавить скин

Добавьте запись в `Config.Skins`:

```lua
{
    id = "seeker_new",
    characterId = "seeker",
    role = Config.Roles.Savior,
    name = "Название",
    title = "TITLE",
    description = "Описание",
    price = 300,
    accent = Color3.fromRGB(86, 220, 232),
    tint = Color3.fromRGB(70, 80, 95),
    previewTint = Color3.fromRGB(170, 190, 255),
    rarity = "РЕДКИЙ",
}
```

Для отдельной 3D-модели скина создайте модель с именем `seeker_new` в `Content.CharacterModels`.

### 6. Добавить эмоцию

Добавьте запись в `Config.Emotions` с `id`, `name`, `symbol`, `line`, `price` и `accent`. Эмоция появится в магазине и может быть выбрана. Визуальный эффект — всплывающая табличка над головой; своей анимации пока нет.

### Изменить тайминги и баланс

- `Config.Round` — лобби, время, задержки.
- `Config.Stamina` — запас, расход, восстановление.
- `Config.Combat.Knife` — урон, дальность, кулдаун, конус.
- `Config.Flashlight` — дальность и угол света.
- `Config.Economy` — стартовый баланс и награды.
- `Config.Content.UseStudioMaps`, `UseStudioCharacterModels`, `UseCustomAbilities` — быстрый выключатель подсистем контента.
- `Config.Content.DefaultMapLighting` — освещение пользовательских карт по умолчанию.

## Ограничения текущей версии

- Управление рассчитано на ПК: мобильных кнопок пока нет.
- Пользовательские 3D-модели персонажей работают как костюмы поверх аватара: они крепятся к его костям и используют его анимации. Отдельный Humanoid/Animator внутри модели не используется.
- Магазин и Tab-список показывают рендер аватара, а не кастомную 3D-модель. Для интерфейса это ограничение текущей версии.
- Эмоции отображаются как всплывающие карточки, без анимационных пакетов Roblox.
- Нет дополнительной цели раунда (генераторы/выходы) — только выживание по таймеру.
- DataStore использует простое сохранение без session-locking. Для крупного релиза стоит перейти на ProfileService/ProfileStore.
- Скины без пользовательской 3D-модели — это цветовой оттенок аватара и контур.

## Проверка

1. Откройте `.rbxlx` в Studio.
2. Запустите **Test → Local Server** с 2 игроками.
3. Подождите 40 секунд в лобби: должен начаться **Last Fighting Soul** на 1:15.
4. Проверьте:
   - магазин по `E` у NPC;
   - покупку скина/эмоции;
   - Tab-список и карточку игрока с двумя рендерами;
   - бег с `Shift` и шкалу выносливости;
   - фонарик на `F`;
   - удар ножом на `ЛКМ`;
   - завершение раунда по таймеру и по смерти всех выживших;
   - возврат в лобби и новый раунд.

С тремя игроками раунд должен длиться **3:00** (1 убийца + 2 выживших).

### Проверка Studio-контента

1. Скопируйте простую модель в `Content.Maps`, добавьте `KillerSpawn` и `SurvivorSpawn` (Part с `SpawnRole`), нажмите Play. В консоли должно появиться количество карт, а раунд — стартовать на вашей карте.
2. Поместите модель `seeker` в `Content.CharacterModels`, соберите её из частей с именами R15. При спавне аватар должен скрыться, а костюм — двигаться вместе с ним.
3. Переименуйте `_TemplateAbility` в `Dash` и укажите персонажу `abilityId = "dash"`. В HUD должна появиться клавиша `Q`, а по нажатию — рывок.
4. Ошибки контента ищутся в Output: `ContentService` пишет количество найденных ассетов, `AbilityService` — загруженные способности и ошибки колбэков.
